독립 Matter 브리지

Zigbee를 Matter로 연결합니다.

Zigbee2MQTT의 검증된 장치·converter 경로를 유지하면서 MQTT 브로커 경계를 in-process bridge bus와 Matter adapter로 교체합니다.

소스 구현 완료 · 플랫폼 수용 검증 대기

제공 기능

Zigbee runtime

코디네이터 탐색, pairing, interview, availability, 그룹, binding, converter와 OTA 경계를 Zigbee-herdsman 중심으로 유지합니다.

Matter 노출

장치를 영속 Matter endpoint로 매핑하고 commissioning, fabric, reporting 및 복수 브리지 identity 경계를 제공합니다.

Home Assistant

Direct, Matter, Hybrid adapter 경로를 제공합니다. HAOS add-on의 runtime 데이터는 /data에 저장됩니다.

API와 이벤트

인증된 REST와 WebSocket API로 장치, 명령, 진단, snapshot 및 순서 있는 event replay/resync를 제공합니다.

아키텍처

Zigbee 네트워크가 장치 상태의 기준입니다. Matter는 fabric, ACL, commissioning과 reporting 상태를 담당하며 API와 frontend는 공통 계약을 사용합니다.

네트워크 지도와 언어

기존 Windfront frontend의 Zigbee 네트워크 지도는 /map에서 그대로 제공됩니다. 언어 메뉴도 유지하며, 최초 접속 시 브라우저의 지원 언어를 기본값으로 선택하고 기존 사용자 선택을 우선합니다. 지원 언어가 없으면 영어를 사용합니다.

MQTT topic, device key, protocol identifier는 안정적인 기술 값이므로 번역하지 않고, 화면의 사용자 문구는 frontend 번역 리소스를 사용합니다.

빠른 시작

pnpm install --frozen-lockfile
pnpm run build
pnpm start

Docker는 docker/, Home Assistant OS는 haos/zigbee2matter/를 확인하세요.

프로젝트 상태

소스 구현과 패키징 구조는 마련되어 있습니다. 설치·재시작·업데이트·backup restore, 실제 coordinator 장비, Home Assistant runtime, Matter commissioning, 지원 add-on 아키텍처에 대한 승인된 검증을 완료하기 전에는 제품 전체가 최종 수용 완료되었다고 볼 수 없습니다.
